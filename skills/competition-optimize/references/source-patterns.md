# Source-Backed Strategy-Generation Patterns

Read this when the task needs more than local edits to generate or select its next approach. The examples below come from inspected public source snapshots. They support the stated implementation pattern, not a claim that copying it improves another contest score.

## Produce structurally different candidates

- [KAPSO](https://github.com/leeroo-ai/kapso/tree/a2d110f2c7b09ea0c713a4b426066249371b6987): its [lens planner](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/prompts/ideation_lens_planner.md#L66-L87) grounds parallel roles in how analogous tasks were won, a structurally different alternative and failure modes. The [selector prompt](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/prompts/ideation_selector.md#L22-L63) judges expected progress toward the target and gives different structures more weight when the current line is stalled; the [ensemble implementation](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/ideation.py#L392-L420) actually fans out candidates and selects or synthesizes. Transfer the separation of candidate generation from candidate selection. Adapt its evidence and budget checks to the actual competition contract.
- [CoMind](https://github.com/comind-ml/comind/tree/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38): [solution-path generation](https://github.com/comind-ml/comind/blob/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38/comind/agent.py#L303-L428) creates complete approaches before decomposing and recombining ideas, with an explicit fresh-route branch. This matters when atomic edits all inherit the same architecture. Its fixed route count is a repository choice, not a universal requirement.
- [LLM4AD Next](https://github.com/Optima-CityU/llm4ad_next/tree/c23a45c64a4b1fed322bfefbfe8436eeea32c954): [island policies](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/orchestrator/island_diversity.py#L43-L114) separate successful-memory reuse, corrective memory and memory-free exploration. Its [planner](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/planner/llm_evolution.py#L195-L221) can disable memory and even generate parentless candidates. The transferable point is to preserve an escape from stale assumptions; do not copy its island count or probabilities.

## Reuse registration indexes during historical replay

FunSearch's fixed `cc53f274237d7ab05c19df939edbc1f9616a7c19` snapshot registers evaluated programs through `implementation/evaluator.py:145-155` and `programs_database.py:110-140,191-203`, updating its signature-to-cluster mapping. The next `sampler.py:53-62` call obtains a prompt from that existing mapping (`programs_database.py:104-108,205-234`). OpenEvolve's fixed `515d1bcb7b36ac64bbe028f8d83b5d08315ca4b5` snapshot registers evaluated children (`openevolve/process_parallel.py:363-388,758-769`); `openevolve/database.py:334-340,381-385,512-522` uses the maintained program map for parent and ID lookups, while loading builds that map once (`:817-833`).

The local transfer is narrower: `candidate_archive.read_records` passes its accepted-candidate map to proposal/successor validation and maintains prior string result digests during that read. This removes repeated prefix indexing and result searches without a persistent cache, archive migration, relaxed validation or new sampling policy. Non-string legacy digest equality retains its previous path. The source repositories do not establish this archive's strict duplicate semantics, digest checks or performance; the [fixed-source evidence](/home/lzh/competition-agent-validation/archive-replay-20261023/source-study/source-study.json) and [local measurements](/home/lzh/competition-agent-validation/archive-replay-20261023/REPORT.md) keep those claims separate.

## Separate comparison controls from inherited code

[LLM4AD Next's I1 path](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/orchestrator/eoh.py#L331-L338) actually generates and evaluates with `parents=[]`; the [planner/implementation call](https://github.com/Optima-CityU/llm4ad_next/blob/c23a45c64a4b1fed322bfefbfe8436eeea32c954/src/llm4ad/orchestrator/eoh.py#L461-L494) forwards those parents and an empty implementation base context. [Comind](https://github.com/comind-ml/comind/blob/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38/comind/agent.py#L428-L440) can choose `codebase=None`; its actual coding path [injects and copies an old codebase only when selected](https://github.com/comind-ml/comind/blob/f93dff779b5d40dd3bf28b7b6ba5e39881e02e38/comind/agent.py#L494-L541). Telco's fresh-start reference omission follows the same source-reuse distinction. These systems can retain task context and coordinator history; no complete information isolation follows.

The local transfer is optional [`construction_mode=independent`](iteration-trace.md#declare-an-independent-construction), with verified development controls but no fictitious parent file targets. Proposal, successor, exact trace and bounded pending/trial delivery preserve that distinction; the control's refinement opportunity stays open. Default refinement and actual score comparison remain unchanged. Mode is an Agent declaration, not a novelty or effectiveness certificate. Fixed commits, eight source file hashes and eighteen excerpts are in the [local study](/home/lzh/competition-agent-validation/fresh-construction-20261023/source-study/source-study.json).

## Keep useful complementarity and branch value

- [EoH-S](https://github.com/feiliu36/eoh-s/tree/7d4b1f77d1b101125cd713b1d247e3a2e46cf407) retains candidates by per-instance max-score coverage ([survival selection](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/population.py#L108)) and ranks parent pairs by score-vector L1 distance ([pair selector](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/population.py#L314)). The [actual loop](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/eohs.py#L237) passes that pair to e1 generation, but the [prompt](https://github.com/feiliu36/eoh-s/blob/7d4b1f77d1b101125cd713b1d247e3a2e46cf407/code/llm4ad/method/eohs/prompt.py#L43) supplies descriptions/code without specific case wins. L1 difference does not establish complementary strengths; max coverage is a retrospective envelope, not an executable combined score. Preserve useful case strengths only when they can inform the next implementation.
- [MCTS-AHD](https://github.com/zz1358m/mcts-ahd-master/tree/ee9c4f424503c65a5fd2b899e6620ce86079fedb) keeps searchable ancestors outside the current top-k pool, with progressive widening and remaining-evaluation-dependent exploration ([tree/search code](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts.py#L51-L70), [AHD selection](https://github.com/zz1358m/mcts-ahd-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/source/mcts_ahd.py#L150-L185)). This separates “not currently elite” from “cannot lead to a useful descendant.”
- [The AI Telco Engineer](https://github.com/NVlabs/The-AI-Telco-Engineer/tree/be94f40f4bdd255b3e4dfa8bf32798821813311b) proposes distinct algorithmic families for a metric/complexity frontier, then presents both frontier candidates and selected faithful implementations from other families to the next proposal round ([generation prompt](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/orchestrator_llm.py#L27-L84), [actual loop](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/agent_orchestrator.py#L243-L279)). Its separate [implementation summary](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/orchestrator_llm.py#L91-L115) checks whether the assigned mechanism reached the code, independently of its score. Preserve the distinction between a weak tested family and an idea whose central mechanism was never implemented. Complexity is a task-specific proxy; replace it with the actual contest cost/constraint when needed. The LLM's fidelity verdict still needs code evidence, and the repository's fixed idea counts are not a general requirement.

## Review the mechanism that reached the executed code

Telco's [result processing](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/agent_orchestrator.py#L589-L626) compares the completed workspace's `solution.py` with its assigned idea, stores the verdict in the candidate summary, and [returns that summary and actual code to the next generator](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/agent_orchestrator.py#L243-L279). The [generation prompt](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/orchestrator/orchestrator_llm.py#L59-L84) treats a substituted idea as untested, counts families by actual code, and omits unrelated reference code for fresh constructions. Its [evaluation entry](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/tool_lib/base.py#L165-L237) runs the candidate and saves better successful drafts; the verdict remains an LLM interpretation of source, not proof of the parameter-specific executed mechanism.

The local transfer is optional `record --implementation-review <JSON>` on a prospective proposal's executed development or diagnostic successor. It records `fidelity` (`yes`, `partial`, `no`, `unknown`), `actual_mechanism`, `missing_components` and `code_evidence` with candidate source/recipe paths and concrete observations in `detail` (which may cite functions or lines). Archiving binds the report to the proposal, implementation and input identities, and adds source hashes after checking references. Matching `brief` cards and `trial_history` return this `agent_report` to the next construction; exact `trace` preserves the original review. Foreign-contract trial entries keep identity/revalidation pointers without the original verdict or explanation. Missing legacy reviews remain unknown without rewriting old events.

Inspect the cited code before deciding whether to complete missing components, repair, change construction or retain the actual substituted mechanism. A valid high-scoring deviation can remain best; its score does not test the absent planned mechanism. This review does not certify fidelity, change ranking, close frontier opportunities, impose a retry or require a new model call. MLEvolve's [stagnation action](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/engine/agent_search.py#L173-L219) and [Tier 2/3 trajectory prompt](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/evolution_agent.py#L68-L115) support structural escalation, already covered locally; its [review input](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/code_review_agent.py#L63-L69) supplies task and code rather than the assigned plan, so it does not establish an equivalent fidelity check. Fixed commits, source hashes and excerpts are in the [generation study](/home/lzh/competition-agent-validation/next-mechanism-20261023/source-study/generation.json).

## Retrieve measured case strengths for the next implementation

Telco's [off-front sampling](https://github.com/NVlabs/The-AI-Telco-Engineer/blob/be94f40f4bdd255b3e4dfa8bf32798821813311b/src/leaderboard.py#L260) keeps the best faithful implementation from each eligible non-front idea cluster, then samples by scalar metric gap. This exposes useful code outside the leaders; it does not measure case complementarity. ReEvo's [actual selection/reflection/crossover loop](https://github.com/ai4co/reevo/blob/6dce18257da5e11db2d138e417a2fffc5c72d05f/reevo.py#L461) generates and evaluates new code from two executed parents, but [parent selection](https://github.com/ai4co/reevo/blob/6dce18257da5e11db2d138e417a2fffc5c72d05f/reevo.py#L302) and better/worse labels use scalar objectives. KAPSO's [proposal pool](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/ideation.py#L603) can be synthesized and [delegated to implementation](https://github.com/leeroo-ai/kapso/blob/a2d110f2c7b09ea0c713a4b426066249371b6987/src/kapso/execution/search_strategies/generic/strategy.py#L609); those pool members are unmeasured proposals from one parent, not independently tested complementary implementations.

The local [candidate_profiles.py](../scripts/candidate_profiles.py) reads opt-in `case_profile` evidence through archive `brief.complementary_evidence`. It requires a complete matching comparison, matching profile metric/direction/case IDs, and executed ordinary development snapshots. It retains the first eligible profile per implementation and retrieves at most two references, preferring newly covered actual wins over the current best, then total wins and scalar score. Cards include win/loss examples and verified source/result pointers. This is a retrieval window, not an experiment quota; scalar ranking and the actual best stay unchanged.

Use the examples to inspect mechanisms and construct a successor, then evaluate that code through the task's adapter. Do not report a per-case envelope as gain or implement selection from hidden labels, remembered case winners or validation IDs. Full E/I boundaries, fixed commits, excerpts and hashes are in the local [complementarity evidence](/home/lzh/competition-agent-validation/complementarity-study-20261023/source-study/complementarity.json) and [combination evidence](/home/lzh/competition-agent-validation/complementarity-study-20261023/source-study/combination.json); see the [implementation study](../../../docs/source-study-20261022.md#逐-case-胜例进入下一次构造). No contest-score benefit follows from these source paths alone.

## Revise conditional learning and feed it into construction

At fixed ReEvo commit `6dce18257da5e11db2d138e417a2fffc5c72d05f`, `reevo.py:325–348` contrasts executed better/worse programs, `:380–405` combines prior reflection with new observations and writes the revised text, `:445–456` feeds it to mutation, and `:479–484` evaluates the resulting programs. Failed executions are excluded from this reflection selection (`:307–320`). The write path alone does not establish a recovery read, and the reflection text does not bind original result identities.

At ShinkaEvolve commit `8adc053a2ce4511ad2ac310e004c530a73fb974a`, `shinka/core/async_runner.py:4450–4468` updates recommendations after an evaluated program. Later generation obtains recommendations (`:2637–2650`), passes them to the sampler (`:3648–3653`), and generates code (`:3677–3685`) that can be submitted for evaluation (`:2920–2941`). `shinka/core/sampler.py:117–124` injects them into non-cross prompts. The study found save/load methods but did not establish an actual runner recovery chain. Its three-stage summarization calls and fixed sampling defaults are outside this transfer.

The shared useful mechanism is revised learning **consumed by subsequent construction**, beyond saving a summary. Local optional `record --learning` attaches conditions, next action, limitations and evidence IDs to an actual measured successor. `brief.scoped_learning` retrieves current revisions; a prospective `learning_from` names the report that informed the next implementation. Evidence and the explicit revision chain stay in the existing append-only archive, without another provider or database. The exact schema, eligibility and semantic boundaries are in [conditional learning](iteration-trace.md#carry-conditional-learning-into-the-next-construction). Fixed source files, 23 excerpts and eight hashes are preserved in the [source study](/home/lzh/competition-agent-validation/scoped-learning-20261023/source-study/source-study.json). These paths establish the mechanism, not a contest-score improvement.

## Make feedback change the next proposal

- [HeurAgenix](https://github.com/microsoft/HeurAgenix/tree/e84bfb19e785ae2d670af6e3ab68890c71c536ea) supplies positive and negative solutions plus trajectories to locate a bottleneck operation, then revises the rule governing that operation ([evolver](https://github.com/microsoft/HeurAgenix/blob/e84bfb19e785ae2d670af6e3ab68890c71c536ea/src/pipeline/heuristic_evolver.py#L249-L327)). Adapt this by comparing the decisions or objective terms that separate a strong candidate from a weak one; a final score without a mechanism is a poor lesson.
- [MLEvolve](https://github.com/InternScience/MLEvolve/tree/f4a37b96c948bfed6564e62f3229e0b38e908d33) escalates stalled work from parameter edits toward module/representation and paradigm changes, and can synthesize a route from independent successful branches ([tier policy](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/evolution_agent.py#L68-L122), [branch aggregation](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/agents/aggregation_agent.py#L76-L150)). Use the escalation when observations point to a ceiling, not after an arbitrary number of trials.
- [RefineEvo](https://github.com/samwu-learn/refineevo/tree/7de015d5230e32b8b85fa83a3ecc55d117489138) labels experience by whether a candidate strictly beats its parent, retrieves it by semantic relevance and operator goal, then updates or removes experience based on reuse outcomes ([experience pool](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/pool_interface.py#L76-L120), [reuse feedback](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/pool_interface.py#L220-L285)). Transfer conditional, parent-relative lessons instead of storing unsupported universal rules.

For code or model search with costly evaluation, separate proposal ranking from score evidence. In the [Predict-Before-Execute repository's bundled AIDE fork](https://github.com/zjunlp/predict-before-execute/tree/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide), `_improve_batch` creates several distinct improvement sketches and implementations ([candidate generation](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/agent.py#L368-L433)); its world model predicts pairwise winners, leaves low-confidence comparisons unresolved, and tournament-ranks the candidates ([pairwise confidence handling](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/world_model.py#L303-L390), [tournament](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/world_model.py#L455-L651)). The caller executes only candidates within a predicted top-k, samples execution, and forces the top candidate to run if that sample skipped all candidates ([execution gate](https://github.com/zjunlp/predict-before-execute/blob/c4d52cf99bd870d830b456ac7c0684aec1aef375/mle-bench/agents/aide/aide/agent.py#L633-L748)). This is an LLM-based screening policy that trades evaluator calls for model calls; it does not establish that the ranking is accurate or that it improves another task. Preserve exploration or periodically check the ranking against real outcomes.

Do not copy this snapshot's comparison cache as written. The cache key sorts the two code hashes, but the cached `winner_idx` is relative to the original `(node_a, node_b)` order; reversing the pair can therefore return an index for the wrong candidate. The cache is also a class-level map keyed only by code, so comparisons can be reused across different task descriptions or model settings. This is a static code-path issue, not a locally reproduced failure. A safe adaptation must canonicalize both key and winner identity (or invert the index on reversed lookup) and include all prediction context in cache scope.

[RD-Agent's feedback contract](https://github.com/microsoft/RD-Agent/tree/484776c211e4fbbeef03e0ec00d6bbee7362a4f4) compares a candidate with the current best using code diffs, aligned metrics and metric direction ([feedback](https://github.com/microsoft/RD-Agent/blob/484776c211e4fbbeef03e0ec00d6bbee7362a4f4/rdagent/scenarios/data_science/dev/feedback.py#L28-L113)); if it identifies that evaluation is misaligned with the task, it clears the result and rejects promotion. A useful search record can add parent-relative gain, strategy family, failure signature and evaluation cost so selection balances demonstrated progress with underexplored routes. Keep hidden/test labels out of proposal selection.

## Use diagnostic interventions to choose the next construction

In the fixed [MLE-STAR source](https://github.com/google/adk-samples/tree/7d187b6f97522915a153b1cdc30a8f4a164c7b5a/python/agents/machine-learning-engineering/machine_learning_engineering/sub_agents/refinement), the [actual sequence](https://github.com/google/adk-samples/blob/7d187b6f97522915a153b1cdc30a8f4a164c7b5a/python/agents/machine-learning-engineering/machine_learning_engineering/sub_agents/refinement/agent.py#L346-L487) executes/debugs an ablation, summarizes it, extracts a plan/code block, implements and refines. The [instruction builders](https://github.com/google/adk-samples/blob/7d187b6f97522915a153b1cdc30a8f4a164c7b5a/python/agents/machine-learning-engineering/machine_learning_engineering/sub_agents/refinement/agent.py#L117-L180) pass actual ablation results into that summary and then into the next plan. Its [outer update](https://github.com/google/adk-samples/blob/7d187b6f97522915a153b1cdc30a8f4a164c7b5a/python/agents/machine-learning-engineering/machine_learning_engineering/sub_agents/refinement/agent.py#L29-L96) selects the next solution from executed improvement results and separately retains ablation/code-block history. The [ablation prompt](https://github.com/google/adk-samples/blob/7d187b6f97522915a153b1cdc30a8f4a164c7b5a/python/agents/machine-learning-engineering/machine_learning_engineering/sub_agents/refinement/prompt.py#L13-L46) uses validation and excludes test data.

Transfer this distinction: a deliberately weakened intervention can answer a design question without being a failed contender. Locally, explicit `role=diagnostic` retains the control, executed evidence and interpretation for `diagnostic_evidence` and `trial_history`; ordinary development results alone rank contenders and drive objective/comparison reviews. This role/schema design is a local adaptation. Do not automatically relabel regressions, treat explanations as causal proof, force full ablations every round or copy MLE-STAR's fixed loop/retry counts. Diagnostics must lead to a useful construction decision when that is the task. See [recording semantics](iteration-trace.md#diagnostics-and-contenders) and [implementation study](../../../docs/source-study-20261022.md#诊断试验指导构造而不参与候选排名).

## Recall the tested hypothesis with its outcome

- RefineEvo stores the evaluated parent/offspring trajectory and objective delta as experience ([trajectory and persistence](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/evo_interface.py#L716-L774)). Its actual [generation path](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/evo_interface.py#L834-L844) queries the pool using the selected parents and operator goal, separates successful/failed memories, and [inserts them into the operator prompt](https://github.com/samwu-learn/refineevo/blob/7de015d5230e32b8b85fa83a3ecc55d117489138/evo_interface.py#L280-L289). The useful mechanism is returning concrete prior attempts and outcomes to candidate generation. Semantic similarity and natural-language applicability alone do not establish an exact evaluation contract.
- OpenEvolve retains evaluator artifacts with the executed child and later [passes parent artifacts to prompt construction](https://github.com/algorithmicsuperintelligence/openevolve/blob/515d1bcb7b36ac64bbe028f8d83b5d08315ca4b5/openevolve/process_parallel.py#L158-L201); the [sampler](https://github.com/algorithmicsuperintelligence/openevolve/blob/515d1bcb7b36ac64bbe028f8d83b5d08315ca4b5/openevolve/prompt/sampler.py#L147-L171) places both evolution history and enabled artifacts in the actual generation message. Its `previous_programs` are drawn from top performers at this call site. This supports carrying real diagnostics into generation; it does not implement recall of every old negative trial.

The local `trial_history` view joins the existing prospective proposal to its executed outcome, retrieves a recent trial related to the current/best implementation, and rotates the remaining historical slot independently of score. It carries the tested change, expected observation and source/result identities together, as motivated also by HeurAgenix's concrete positive/negative trajectories above. First-parent contract ownership, exact-contract gains and exposure digests are local evidence rules. This adaptation adds no semantic database, distilled causal rules, automatic mechanism blacklist or additional model call. Failure remains scoped to the tested implementation and measurement. See [retrieval semantics](iteration-trace.md#retrieve-evidence-for-the-next-implementation) and [the implementation study](../../../docs/source-study-20261022.md#已完成试验影响下一次构造).

## Check the idea before translating it into code

- [CodeSIM](https://github.com/kagnlp/codegenerator/tree/9cf09ee6c788bfda3b7e1524e88be3447098eb24) manually simulates a proposed plan on sample inputs before coding, then traces failures to distinguish a bad plan from a bad code translation ([controller and prompt](https://github.com/kagnlp/codegenerator/blob/9cf09ee6c788bfda3b7e1524e88be3447098eb24/src/promptings/CodeSIM.py#L190-L305), [debug classification](https://github.com/kagnlp/codegenerator/blob/9cf09ee6c788bfda3b7e1524e88be3447098eb24/src/promptings/CodeSIM.py#L479-L505)). For optimization, walk a few states or updates through the proposed rule and check its invariant and coupled objective terms. This catches reasoning errors; it does not replace execution or scoring.

## Sustain a search across contexts

- [MLEvolve's action selection](https://github.com/InternScience/MLEvolve/blob/f4a37b96c948bfed6564e62f3229e0b38e908d33/engine/agent_search.py#L173) changes stalled branches to evolution/fusion.
