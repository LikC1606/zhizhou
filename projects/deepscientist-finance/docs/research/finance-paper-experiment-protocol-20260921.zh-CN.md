## 1. 论文问题与可否证主张

核心问题：在相同金融研究环境和明确资源范围内，累积实验记忆与诊断，能否使自主 Agent 更有效地发现对现有模型具有稳定增量的因子？

三个需要分别检验的主张：

| 主张                                         | 对应实验                  | 不支持时如何处理                                            |
| -------------------------------------------- | ------------------------- | ----------------------------------------------------------- |
| 同一研究状态下，诊断提升下一批候选的稳定增量 | A：固定状态的一步配对研究 | 不宣称诊断改善搜索；区分信息可用、信息理解和经济效果        |
| 完整 DeepScientist 的池级搜索有竞争力        | B：同环境外部 Agent 对比  | 报告劣势与成本，不用内部消融替代外部比较                    |
| 冻结发现能在未用于开发的数据上延续           | C：独立评价               | 不将 Development 改善称为泛化，不事后改方法重新选择测试结果 |

可靠运行是必要条件，不单独构成上述有效性主张。当前设计不承诺正向结果，也不以“full 必须胜出”决定选例、预算或停止。

## 3. A：固定研究状态的一步实验

### 3.1 先做便宜且有辨识力的实验

从历史开发记录固定六个状态，选择规则只依据来源、轮次，不依据收益：balanced 前瞻 rep-01 和 rep-02 的 full_feedback 分支，各取第 1、3、5 轮提交后的状态。每个状态只包含当时已经完成的历史和池；不带该时点之后的候选或结果。六个状态都纳入，不挑成功案例。源目录为 `output/strategy_discovery/shared-feedback-balanced-replications-v2/rep-{01,02}/full_feedback`。

这些是开发案例，且来自 full 的轨迹，有来源选择偏差；它们用于诊断研究过程，不能代表所有方法状态的无偏总体。后续确认若需要过程结论，应使用预先固定、来源平衡或独立构造的新状态集，不能把本六例标成独立确认。

每个状态三条件，各三次独立模型响应，每次五名额：共 54 个原始请求、270 个候选名额。此数量是开发诊断的成本上限设计，不是统计功效结论。每个请求最多一次既有 JSON 修复，最多 108 次物理调用（不含任何另行授权的探针）；未知结果不自动重发。无累计 token 淘汰门槛，全部报告成本。本规模未获执行授权。

### 3.2 对照的准确含义

| 条件            | 模型可见内容                                     | 可解释的差异                                     |
| --------------- | ------------------------------------------------ | ------------------------------------------------ |
| no_feedback     | 相同静态模型/DSL/数据边界，无动态池和历史        | 无反馈简单搜索；与 full 比是整个动态信息包的作用 |
| scalar_feedback | 同一当前池、公共压缩历史、符号等价记忆、逐折标量 | full 的严格诊断对照                              |
| full_feedback   | 与 scalar 完全相同的公共部分，加诊断             | 相对 scalar 的差异才是增添诊断的效应             |

full 去掉诊断后须与 scalar 的序列化公共上下文一致；no 无隐藏动态信息。基础模型契约和算子说明三组相同。没有注册模型 seed 时只称独立重复请求，不承诺同 seed 同随机流。每个状态的条件调用顺序事先轮换，避免把服务时段固定绑定到某条件。

每批候选均对该固定状态的同一池评价；本实验不把某条件的 winner 写成下一批的起点。候选、符号、基础特征、模型训练、费用和共享决策保持原规则。不把三个条件的候选合并后再择优，不让一组看到另一组的响应。

### 3.3 指标、失败与统计单位

主指标：每个原始名额产生“完整 canonical、通过原风险条件、D1/D2 均正增量”的比例；非法、修复耗尽、重复无 trial 等均保留在名额分母，缺失数值不补零。此指标不是最终入池率。

关键次指标：每批按原共享决策得到的池增量，包括 NO_CHANGE 的实际原池结果；需要真实原池证据，不能因运行失败填零。工程中断单列完成率和缺失，不在成功子集上冒称全样本平均。

过程指标：有向信号重复、同池重试/跨池复测、算子理由一致性、历史引用正确性、诊断可用/可见覆盖、input/output tokens、物理请求及评价成本。理由一致性采用预写核查表，隐去方法标签复核，保留原文与理由；不能根据收益高低判定“解释正确”。

分析先按状态汇总三个重复，再报告六个状态的配对差异和完整分布。不能把 270 个名额当作 270 个独立市场样本；这些状态也共享市场、轨迹，不作大样本显著性宣称。首要比较 full-scalar；full-no 为次要信息包比较。收益增量不在不同测量池间直接混算成统一候选质量。

停止规则：固定名额执行完或出现真实无法恢复的阻塞；不因收益好提前结束，不因收益差追加。若修复尚不能保证 frozen input、预算及来源正确，先停止工程运行，不用多采样补偿错误。

## 4. B：端到端主实验

方法最低集合：固定 Alpha158、无反馈单 Agent、DeepScientist full、AlphaAgent、RD-Agent factor-only。scalar 保留为内部消融。外部方法须使用其原生研究迭代和记忆，不能换成同一提示词生成器；RD-Agent factor-only 不称完整联合优化方法。

所有 Agent 使用用户指定的 glm-flash 服务绑定、同数据/标签/基础模型/交易费用和可用字段。统一提供准确 DSL 说明。若外部方法的原生代码表达范围比 DSL 更广，先核对可表达子集；不能静默删掉它的优势后仍称完整方法。

分两种报告口径，不混为一个排名：

- 共同 evaluator/池准入轨道：保留原研究生成过程，统一下游准入及池容量。回答共同框架中的搜索能力，名称注明 adapted。
- 原生选择轨道：只有原生选择和多轮真正接通后才报告，以冻结的原生因子集合进入共同下游。它是补充完整性检查，不可将两轨最好结果择优拼表。当前未实现、未授权。

主预算以原始候选机会定义，非法也消耗名额；同名额上的有限修复另记工作量，跨轮重复提议仍占新名额，缓存不增加搜索机会。训练/账户调用与实际候选评价量同时报告。不能只以“成功评价数”停止而让高失败方法无限生成。

具体主预算、各方法物理调用活性上限、单次输出上限与独立运行数必须在离线基线完整性核查及成本诊断后冻结。目前 runner 限五轮，不能在文档写二十轮就当作已支持；不直接增加轮次上限。不得沿用当前单 Agent 的 15 次调用上限压缩外部多阶段方法。累计 token 不作结果淘汰标准。

建议候选机会学习曲线报告共同检查点与最终固定终点，最终池是主结果，临时最佳 trial 只是过程数据。主比较为 DeepScientist 对两个外部方法；同时报告无反馈基线，不能仅赢 scalar 就宣称方法优势。多重比较及置信区间口径在主预算冻结时一起确定。

重复单位是完整独立搜索运行。重复数依据有意义的最小收益差、独立运行差值变异及资源确定；不能用两个 pilot 差值估计后宣称已有充分功效。市场层面另报告考虑日期依赖的配对 block bootstrap，不能把搜索重复和交易日混为独立样本。不以挑出最佳 seed、最佳市场或最佳训练种子作为主表。

## 5. C：冻结后的独立评价

先建立已有数据暴露清单，确定未用于开发、未参与选方法的区间或市场；本文不打开任何受保护数据。没有合格未暴露数据，就将论文结论限于开发阶段搜索过程，明确独立泛化阻塞。

在获单独授权前，冻结所有方法的实现、最终池/符号、超参数、预算、交易规则与主要指标。独立评价使用固定训练日程和所有方法一致的规则，不能见结果后重选池、改费用、挑 seed 或改变停止点。所有合格冻结运行一次性统一评价。测试失败要如实报告；修改后再用同一测试期只能作为探索性结果。

## 7. 执行顺序与交付

下一项仅做 A 的离线准备：固定六个状态的来源清单和时点截止；复用已保存工件，不读新的市场数据。实现/验收最小状态投影，证明每组 evaluator 起点相同、full-scalar 公共输入相同、no 隐藏状态、一次请求不会改变其他任务、恢复不重采样。准备授权 false 的计划；没有全部通过就不发模型请求。

并行于设计核查可只读核对外部 adapter 调用链，但不启动付费基线。A 的开发诊断完成后按预定指标解释，再冻结 B 的资源和独立运行数；不要边看结果边扩大为主实验。
