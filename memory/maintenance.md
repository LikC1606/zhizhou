# 记忆维护约定

状态：confirmed。范围：本知识库及读取它的 AI 工作流。
来源：用户于 2026-11-16 在 zhizhou 项目对话中确认长期积累、多工具使用，以及 AI 直接记录明确偏好、纠正和已确认结论。

## 什么内容值得记录

记录会影响以后工作方式的明确偏好、用户纠正、已确认结论和可复用经验。把具体情境写清楚，让下次任务知道它何时适用。运行进度、整段会话、一次性临时选择继续保存在原项目需要的位置。

AI 可以直接把用户明确表达的内容落盘，无需为每条内部记忆再索取确认。保留具体 source、scope、日期和确认状态，不增加用户没有说过的要求。来源可以是本次对话中的准确表述或可定位的项目文档。

AI 自己提出的建议使用 `pending`；只有用户明确接受后，才将对应内容改为 `confirmed`。用户的沉默、AI 的推断和一条尚未核验的对话陈述都不等于确认。

## 按范围保存

| 范围 | 含义 |
| --- | --- |
| `global` | 跨项目适用的工作方式、沟通偏好和通用约束 |
| `research` | 科研方法和研究协作约定 |
| `project:<id>` | 指定项目的经验、局部约束与结论 |

选择最准确的范围。TheoremOS 的解题干预限制仍属于 TheoremOS；某次运行操作的授权不会自然延续到以后。机器路径属于机器配置，不应变成所有服务器的固定路径。

重要科研决定和科学定义继续以相应项目的 Protocol、`research/decisions/` 为依据。本仓库保存可复用约定、来源和必要索引，避免创建一份与项目研究记录竞争的真相。

## 日常操作

1. 先检索是否已有同义记录，读取相关来源和范围。
2. 使用 `./zhizhou note` 记录新经验，或在确认修订时更新对应的既有记录。
3. 保留纠正的来由；明确被替代内容，避免两条相反约束同时被当作当前规则。
4. 检查 `git diff`。修改核心规则或 skills 时，运行检查并重新安装工具副本。

工具入口指向本仓库的 `memory/INDEX.md`，后续任务按范围读取已确认 notes。新增 note 不需要重写所有入口；核心规则和 skill 的已安装副本需要通过 `install --apply` 更新。

各服务器通过 Git 或用户选择的备份方式交换仓库内容。项目不自动 `git commit`、`git push`、修改外部文档或向其他人发送经验记录。

当前远程仓库已公开。后续收录适合公开分享的经验；个人隐私、凭据和未获公开授权的项目细节继续保存在相应的私有记录中。

不要收录登录凭据、密钥和无关个人信息。这个约定用于准确维护长期知识，不要求为每条日常经验新增审批、审计或证明文件。
