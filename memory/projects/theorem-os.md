# TheoremOS：系统维护与解题干预的边界

本节适用于 TheoremOS 及其数学库、solver、运行记录与交付目录。
来源：用户于 2026-11-15 明确要求“以后在没有我的允许下都不能直接对解题过程进行干预。要做系统级修复。”

## 未经明确授权，不直接干预具体解题

- 不向正在求解的 Lead 或 worker 投递逐题指导、数学纠正、证明、证书或定向资料包；不以修改 scratch 文件代替指导投递。
- 不手工修改具体题目的证明源码、研究笔记、任务图、路线、责任分配或进度状态。
- 不替具体题目提交或接受证明，不制造 handling decision、checkpoint 或 worker turn。
- 不因维护任务擅自切换、重启求解进程，或改变其模型、预算、题目、并发与轮换策略；运行操作须有明确相应授权。
- 过去的逐题干预授权不自动延续到本规则生效之后。用户重新授权时，仅在其明确范围内执行。

此限制针对维护者或外部助手的人为逐题介入；求解系统可按其既有策略自主研究。
已有证明与指导作为历史证据保留，不擅自撤销或改写。

## 系统级修复的工作方式

- 可以只读分析真实轨迹、源码与产物，将失败路径提取到隔离、可丢弃的复现环境。
- 修复通用调度、上下文、恢复、错误反馈、工具、检索、共享库接口与验收实现，并完成适当测试。
- 不把题号、特定定理答案或人工写好的证明编码进调度与提示来代替通用修复。
- 共享机制与库接口的开发不授权将特定题目的新证明注入正在运行的任务。
- 实现完成、测试通过、已激活和数学原题通过分别报告。系统与原生 Codex 的比较须分清工程功能与实测收益；人工逐题协助不能计为系统自主能力。
